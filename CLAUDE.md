# The Dog Diary (demo version)

English demo version of a web app built for a veterinary clinic: medical
profiles of animals — what was done, when, who the owner is, which medications
were prescribed and when the next vaccination is due.

This copy is for a public portfolio repo. It has its **own database and
Cloudinary account** and contains **only made-up data** — never copy real
clinic data, credentials or `.env` values into it. The UI is entirely in
English (the original private project's UI is in Bulgarian).

**Communication:** the maintainer prefers replies in Bulgarian, in plain
language without jargon. Documentation (README, this file, commit messages) is
in English. Ask before riskier steps (push, delete, etc.).

**GitHub:** https://github.com/vaYordanova2005/dog-diary (public repo, branch `main`).

## Tech stack

- **Next.js 16** (App Router, TypeScript, Turbopack, `--src-dir`)
- **Tailwind CSS v4**
- **Prisma ORM v7** + **Neon** (managed PostgreSQL)
- **NextAuth v5 (beta, "Auth.js")** with the Credentials provider
  (**username** + password, bcrypt hash — `User` has no email field).
- **Cloudinary** for photo/PDF/Word attachments.

## Roles (`Role` enum in `prisma/schema.prisma`)

- `ADMIN` — developer only; not created by the demo seed.
- `DOCTOR` — full access.
- `INTERN` — can add/edit everything but **cannot delete**. Guarded on two
  levels: the UI hides the "Delete" buttons ([src/app/dogs/[id]/page.tsx](src/app/dogs/[id]/page.tsx),
  [src/components/EditableListItem.tsx](src/components/EditableListItem.tsx)),
  and `ensureCanDelete()` in [src/lib/actions.ts](src/lib/actions.ts) throws
  if someone calls a delete server action directly.
- Registration at `/register` always gives `INTERN`. In production it is
  disabled unless `REGISTRATION_CODE` is set (the form then asks for that
  "clinic code").
- Deleting always asks "Are you sure?" ([src/components/ConfirmSubmitButton.tsx](src/components/ConfirmSubmitButton.tsx)).
- The role is re-read from the database on every `auth()` (jwt callback in
  [src/auth.ts](src/auth.ts)) — a change via prisma studio applies instantly.
- Every page and server action calls `requireUser()`
  ([src/lib/session.ts](src/lib/session.ts)). A deleted user is sent to
  `/logout` (clears the cookie), not straight to `/login` — otherwise the
  proxy still sees the old cookie and you get an infinite redirect loop.
  New pages and actions must call `requireUser()` too.
- Usernames are case-insensitive at login/registration.
- Changing another user's role is manual only, via `npx prisma studio`.
- The login form has "Continue as doctor" / "Continue as intern" buttons that
  prefill the username and only ask for the password.
- Any signed-in user can change their own password at `/password`.

## Gotchas already hit (don't rediscover them)

1. **Next.js 16 renamed `middleware.ts` → `proxy.ts`.** With `--src-dir` the
   file must be `src/proxy.ts`, NOT in the root — otherwise it silently
   doesn't run and routes aren't protected.
2. **Prisma 7 requires a driver adapter.** `PrismaClient` is always created
   with `@prisma/adapter-pg` (see [src/lib/prisma.ts](src/lib/prisma.ts) and
   [prisma/seed.ts](prisma/seed.ts)).
3. **The generated Prisma client has no `index.ts`** (`src/generated/prisma/`).
   Import from `@/generated/prisma/client`.
4. **Auth config is split in two** because `proxy.ts` runs in the Edge
   runtime, where Prisma doesn't work:
   - [src/auth.config.ts](src/auth.config.ts) — light config, no providers; used by `proxy.ts`.
   - [src/auth.ts](src/auth.ts) — full config with the Credentials provider and Prisma.
   Don't merge them back into one file.
5. **`tsx` doesn't load `.env` automatically** — `prisma/seed.ts` imports `dotenv/config` first.
6. **The `pg` SSL warning** is silenced with `&uselibpqcompat=true` in `DATABASE_URL`.
7. **`npx prisma init` installs auto-generated "skills" folders**
   (`.claude/skills`, `.agents/skills`, `.windsurf/skills`, `skills-lock.json`)
   — delete them if you run it again.
8. **`AGENTS.md`** is regenerated by `next dev` — don't edit it.
9. **`prisma migrate dev` doesn't work non-interactively** here; write new
   migrations by hand as a folder in `prisma/migrations/` and run
   `npx prisma migrate deploy`. The `role_username_refactor` migration was
   hand-written with `RENAME COLUMN`/`RENAME VALUE` to keep existing rows.
10. **Tailwind v4 removed `cursor: pointer` from buttons** — restored globally in `globals.css`.

## Seed / demo data

`npm run seed` ([prisma/seed.ts](prisma/seed.ts)) is idempotent: it creates
the `doctor` (`doctor123`) and `intern` (`intern123`) accounts if missing and
fills an **empty** database with a handful of made-up animals and owners.
Vaccination dates are relative to "now", so the demo always shows one overdue
and one upcoming dose.

`.env` (**not in git**) holds `DATABASE_URL`, `AUTH_SECRET` and the optional
`CLOUDINARY_*` / `REGISTRATION_CODE` values.

## File attachments (Cloudinary)

- Upload flow: browser → `prepareUpload()` (server action: checks type/size,
  returns a signed request) → browser uploads **directly** to Cloudinary
  (Vercel rejects large request bodies) → `saveAttachment()` re-reads the
  resource from Cloudinary (doesn't trust browser-sent url/size), re-checks
  the real size and saves it. If saving fails, the uploaded file is removed
  from Cloudinary so it doesn't become an orphan.
  UI: [src/components/AttachmentUploader.tsx](src/components/AttachmentUploader.tsx),
  helpers in [src/lib/cloudinary.ts](src/lib/cloudinary.ts) (server) and
  [src/lib/fileTypes.ts](src/lib/fileTypes.ts) (allowed types, shared with the browser).
- **Attachment/folder server actions return `{ error }` instead of throwing.**
  In production Next.js hides the text of thrown errors. Client components
  call them through `runAction()` ([src/lib/runAction.ts](src/lib/runAction.ts)),
  which shows the error in an alert instead of crashing the page.
- Dropping files from the computer works anywhere in the "Photos and
  documents" section; dropped onto a folder (`data-folder-id`), they go
  straight into it. Drops elsewhere on the page are ignored.
- Folders: files are moved with the ⋯ menu ([src/components/FileMenu.tsx](src/components/FileMenu.tsx))
  or by dragging ([src/components/FileDnd.tsx](src/components/FileDnd.tsx)).
  Any user can create/rename/move; deleting files needs DOCTOR/ADMIN.
- Allowed: images (resized to max 2000px, converted to JPEG) stored as
  `image`; PDF/DOC/DOCX stored as `raw`. Max 10 MB. The type is detected by
  MIME type, falling back to the file extension.
- Without `CLOUDINARY_*` env vars the uploader shows "File storage is not configured."

## Data model ([prisma/schema.prisma](prisma/schema.prisma))

- `User` — clinic staff (role ADMIN/DOCTOR/INTERN), logs in with `username`.
- `Owner` — animal owner (name, phone, email, address).
- `Dog` — animal profile (name, `species` — defaults to "Dog", breed, gender,
  birth date, weight, microchip no., notes), belongs to one `Owner`. The model
  is called `Dog`, but the UI talks about "animals".
- `MedicalRecord` — examination/procedure (title, date, vet, description).
- `Vaccination` — vaccine (name, date given, next dose, notes).
- `Medication` — medication (name, dosage, start/end, notes).
- `Attachment` — photo / PDF / Word file (name, url, `publicId`,
  `resourceType` image|raw, bytes), stored in Cloudinary. Optional `folderId`.
- `AttachmentFolder` — per-animal folder; deleting it keeps its files (`SetNull`).

`MedicalRecord`/`Vaccination`/`Medication`/`Attachment` all have `dogId` with
`onDelete: Cascade` — deleting an animal deletes its whole history
(`deleteDog` also removes its files from Cloudinary first).

## Project structure

```
src/
  app/
    page.tsx              → animal list: search + filters (searchParams)
    login/ logout/ register/ password/
    dogs/new/page.tsx     → new animal form (+ pick/create owner)
    dogs/[id]/page.tsx    → profile: owner, examinations, vaccinations,
                            medications, photos and documents
    api/auth/[...nextauth]/route.ts
    layout.tsx            → header: name + role, "Change password", "Sign out"
  components/             → client components
  auth.ts / auth.config.ts / proxy.ts
  lib/                    → prisma.ts, session.ts, actions.ts, cloudinary.ts, ...
prisma/                   → schema.prisma, seed.ts, migrations/
```

## UI/UX preferences

- Number input (weight) — no spinner arrows (`.no-spinner` in `globals.css`).
- Date input — native `<input type="date">`; the popup stays native.
- Colors: orange buttons `#ff964f` (hover `#f2803a`), page titles in a peach
  box `bg-[#fbe4cf] rounded-md px-4 py-2`, panels `bg-[#fff1e3] border-[#fbe4cf]`.
- Next.js dev-only overlays are fine — they disappear in production.

## Useful commands

```bash
npm run dev               # dev server (Turbopack), http://localhost:3000
npm run build             # production build (also type-checks)
npm run seed              # demo accounts + sample animals (idempotent)
npx prisma migrate deploy # applies migrations
npx prisma studio         # visual database browser
```

## Deployment

Hosted on **Vercel**, connected to GitHub — every push to `main` deploys.
The `build` script runs `prisma generate`. Vercel env vars: `DATABASE_URL`,
`AUTH_SECRET`, optionally `REGISTRATION_CODE` and `CLOUDINARY_CLOUD_NAME`,
`CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
